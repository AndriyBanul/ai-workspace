AI Workspace — мультимодальна RAG-платформа

Інтерактивний опис поточної архітектури репозиторію. Користувач створює workspace, завантажує документи, аудіо, зображення, відео або додає URL веб-сторінки чи YouTube. Система витягує знання, індексує його у векторному пошуку та відповідає на запитання з веріфікованою доказовою базою (цитати на рівні чанків із таймкодами).

Стиль: модульний моноліт (ADR 0001). Один виконуваний Spring Boot застосунок, одна БД, один Git-репозиторій — але з жорстко розділеними бізнес-модулями, які механічно мапуються на майбутні мікросервіси.

Три кити продукту

1. Інгестія знань — документи, веб, YouTube, медіа → нормалізований текст → чанки → ембеддінги → OpenSearch.

2. Пошук і відповіді — hybrid kNN+BM25, RRF, query expansion, розширення сусідів, відповідь Gemini із цитатами.

3. Надійність — durable recovery ledger, leases, fencing-токени, версіоновані generation-и індексу, reconciliation.

Модулі

Натисніть картку, щоб побачити деталі, залежності та ключові класи. Діаграма компонентів нижче використовує ті самі модулі — клік по вузлу теж відкриває панель.

Межі модулів

Дозволені напрямки залежностей (з apps/build.gradle). Усе інше — помилка збірки.

api          → shared, documents, images, videos, audio,
               knowledge, orchestrator, users, workspaces
orchestrator → shared, audio, documents, images, videos, knowledge, workspaces
knowledge    → shared, workspaces
documents    → shared, images, knowledge
audio        → shared, knowledge
images       → shared
videos       → shared
users        → (немає)
workspaces   → (немає)
shared       → (немає)
Правила: apps/api — лише HTTP-адаптер; бізнес-логіка живе у своєму модулі; модулі спілкуються через інтерфейси; контролери заборонені поза api; shared — не звалище, лише справді спільні моделі.

System Context

Діаграма компонентів

Модулі моноліту, їхні дозволені залежності та зовнішні системи. Клік по модулю — деталі.

Потоки даних

Гарантії: рядки job/кроків/recovery створюються в одній транзакції до dispatch → рестарт підхоплює роботу. Черга передає ID джерел, не байти. Кожен документ несе generation; маніфест транзакційно перемикає активну версію. Fencing-токен не дає застарілому воркеру закомітити результат.

Poll (30s)

Підхоплює due- або lease-expired роботу з source_recovery_tasks.

Reconciliation (6h)

Звіряє завершені джерела з файловим сховищем та OpenSearch: переіндексація, звіт про відсутні байти, прибирання «осиротілих» knowledge item.

Атомність: усі вектори створюються до індексації чанк-сету. Якщо ембеддінг запиту недоступний — пошук деградує до BM25. Аудіо чанкується по таймкодованих сегментах; відео/YouTube зараз дають один зведений item (відома асиметрія).

HTTP API

Усі workspace-скошені ендпоїнти перевіряють володіння; крос-власник отримує 404, а не 403 — щоб не розкривати існування ресурсу.

Спостережуваність

Correlation

X-Request-ID валідується/генерується на вході, повертається у відповіді, потрапляє в MDC. Формат логу: %5p [requestId:%X{requestId:-}].

Metrics

Micrometer: спроби/тривалість інгестії, переходи recovery, gauge на активних воркерах і глибині черги. Без sourceId/email/промптів у тегах (кардинальність).

Actuator

/actuator/health, /info, /metrics (метрики — за автентифікацією).

Існує SearchTelemetry для пошуку, але повне спостереження пошуку та tracing — у списку незавершеного.

Стан і наступні кроки

Незакрите

  • Live end-to-end регрес не запускався — потрібні disposable-залежності, контрольовані HTML/YouTube фікстури та ліміт витрат на провайдерів.
  • Спостереження пошуку та tracing — часткові.
  • Identity і distributed rate limiting для multi-node продакшену.
  • TypeScript-міграція фронтенду часткова (лише API + роутинг).
  • Якість на aggregation-питаннях — top-k RAG провалює «усі випадки…».

Що далі (моя рекомендація)

  1. Звузити ICP: винести «Studio» в окремий трек, сфокусуватись на RAG-ядрі.
  2. Завершити live E2E за наявною 58-кейсовою специфікацією.
  3. Вирішити aggregation окремим шаром (summarize-over-evidence + метадані).
  4. Міграції індексу через alias як first-class механізм.
  5. OIDC + розподілений rate limit + revocation сесій.
  6. OpenTelemetry tracing.
