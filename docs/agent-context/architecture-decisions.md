# Architecture Decisions

For important architectural decisions, create an ADR in `docs/adr/`.

Use ADRs for decisions such as:

- Choosing a module boundary.
- Introducing a new infrastructure component.
- Changing database strategy.
- Adding or changing an AI provider abstraction.
- Changing deployment architecture.
- Introducing asynchronous messaging.
- Adding a major dependency or framework.

ADR files should explain:

- Context.
- Decision.
- Alternatives considered.
- Consequences and trade-offs.

Do not create ADRs for small implementation details.
