# OpenCode Agent Permissions — Памʼятка

Коротка памʼятка: як поводитися з підтвердженнями OpenCode, щоб агент не отримав
доступ до секретів, і що саме захищає, а що — ні.

Активний конфіг: `~/.config/opencode/opencode.jsonc` (глобальний).
Для цього репозиторію нічого додатково не потрібно.

---

## 1. Що робить конфіг

| Правило | Дія |
|---|---|
| `shell * → ask` | Кожна команда Shell чекає на ваше підтвердження |
| `shell *.local/share/opencode* → deny` | Блокує команди, що явно звертаються до теки даних OpenCode |
| `shell *opencode.db* → deny` | Блокує команди зі згадкою `opencode.db` |
| `read *.env`, `*.env.* → deny` | Забороняє читати `.env`-файли |
| `read */.local/share/opencode/* → deny` | Забороняє читати будь-що в теці даних OpenCode |
| `read *opencode.db* → deny` | Забороняє читати саму базу |
| `grep *sk-or-*`, `*sk-ant-*`, `*GEMINI_API_KEY*`, `*HUGGING_FACE_API_TOKEN* → deny` | Блокує пошук типових форм ключів |
| `subagent * → ask` | Запуск субагента потребує підтвердження |

Приоритет: **останнє відповідне правило виграє**, тому широкі правила стоять
перед вузькими `deny`. `deny` не перебивається «Allow always».

> Зміни конфігу підхоплюються новою сесією / після перезапуску сервісу OpenCode:
> `opencode service restart`. Поточна сесія може ще працювати за старими правилами.

## 2. Що схвалювати, а що відхиляти

### ✅ Безпечно схвалювати

| Тип команди | Приклад |
|---|---|
| Git-огляд | `git status`, `git diff`, `git log` |
| Збірка/тести проєкту | `./gradlew test`, `./gradlew :api:bootJar` |
| Читання коду | `grep`, `read` у межах `D:\ai-workspace` |
| Локальні утиліти проєкту | `node scripts/...`, `npm test` (у `apps/web`) |

### ⛔ Відхиляти (або перевіряти особливо уважно)

| Червоний прапорець | Чому |
|---|---|
| Будь-яка згадка `opencode.db`, `~/.local/share/opencode`, `credential` | Там лежать ключі у відкритому вигляді |
| Читання `.env`, `*.pem`, `id_rsa`, `*.key`, `credentials*` | Секрети |
| Пошук `sk-or-`, `sk-ant-`, `AIza`, `GEMINI_API_KEY`, `HUGGING_FACE_API_TOKEN`, `HF_TOKEN` | Пошук форм ключів |
| `Get-Content`/`cat`/`type`/`certutil`/`base64` по файлах поза репозиторієм | Обхід читання через shell |
| Скрипти (`node -e`, `python -c`, `powershell -Command`) від агента без зрозумілої мети | Сканер не бачить, що робить скрипт усередині |
| `git push`/`push --force`, видалення даних, `rm`/`Remove-Item -Recurse`, `DROP` | Небезпечні операції (див. `risky-actions.md`) |
| Мережеві команди з файлами з диска (`curl -T`, `scp`, `Invoke-WebRequest -InFile`) | Ексфільтрація даних |
| Доступ до `C:\Users\Andrii\AppData\Local\Temp\opencode\shell\...` | Там зберігаються повні виводи команд, зокрема випадкові секрети |

### 🔎 Правило для «Allow always»
Не зберігайте широкі `always`-схвалення. `shell: Get-Content * → allow` відкриє
читання будь-чого. Якщо сумніваєтесь — натискайте **once**, а не **always**.

## 3. Межі захисту (важливо)

Конфіг суттєво знижує ризик, але **не є гарантією**, поки агент має `shell`
під вашим користувачем. Залишкові шляхи:

1. **Shell-скрипт.** Команда `node read-db.mjs` не містить `opencode.db`, тому
   deny за текстом її не зупинить; а скрипт усередині прочитає базу. Захист тут —
   саме ваше **схвалення** кожної команди.
2. **Пошук за вмістом.** `grep` перевіряється за *патерном*, а не за шляхом.
   Перелічені `grep`-заборони покривають типові форми, але не довільні.
3. **Code Mode (`execute`).** JS у Code Mode викликає інші інструменти, тож кожен
   вкладений виклик усе одно проходить власні правила — але ланцюжок варто читати.

### Найнадійніший рівень — ізоляція
Запускайте агента в **окремому OS-акаунті, контейнері або VM**, які не мають
доступу до `~/.local/share/opencode` та ваших секретів. Тоді жоден shell-доступ
агента ключ не дістане. Альтернатива — забрати в агента `shell` і лишити лише
allowlist безпечних команд.

### Принцип: не тримати секрети там, де працює агент
Ключ у файлі БД у відкритому вигляді — саме такий випадок. За можливості
використовуйте змінні середовища на серверному процесі, а не файли на диску.

## 4. Як перевірити конфіг

```bash
# Переглянути активні акаунти (безпечно, значення не друкуються)
opencode auth list

# Перезапустити сервіс, щоб підхопити нові правила
opencode service restart
```

Якщо потрібно тимчасово послабити правило — редагуйте `opencode.jsonc`
усвідомлено, а не через `Allow always` у діалозі.
